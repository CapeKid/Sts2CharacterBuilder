---
name: create-character-items
description: Create character-specific starting/drop relics and potions with native eligibility tests.
---

Ask whether relics and potions are wanted, collect supplied ideas and independently ask whether AI should add more. Starting relics, reward relics, shops and potions have separate eligibility.
For the supported numeric vocabulary, author design/items.json using [the item contract](../../ITEMS.md): first-turn/each-turn starting and drop relics, and combat-only self potions with Block, draw, Energy and optional Focus. Configure starting_relic explicitly to replace the default starter. Names and relic flavor are authored; effect descriptions are generated. Optional art.icon, art.outline and art.large independently select declared SVG/PNG assets with features.art enabled. Preserve supplied sources and provenance; export silhouettes and large images deliberately and review native crops/readability. Unassigned roles keep explicit native runtime fallbacks. Other targets, effects and timing require project-owned src/Extensions implementations and separate evidence; do not claim a bounded numeric library fulfills arbitrary item ideas.
Run validate, generate, build and a fresh isolated native suite. Preserve frozen Relic_/Potion_ model IDs and generated-file ownership during upgrades. Enabling the feature with empty item data retains existing starter/native-potion behavior; it does not fill a requested library automatically.
Use the existing native model lifecycle as a reference, not the original mod's content or identity. Test owner-specific triggers, combat reset, stacking, acquisition, compendium, save/resume and shop/drop exclusions.
Skip outcome: clear relics/potions and remove starting_relic before disabling items; the character uses native Burning Blood and native relic/potion pools. With items enabled and Focus disabled, the native starter remains unless an authored starting_relic is selected. Do not remove frozen models without an explicit migration.
