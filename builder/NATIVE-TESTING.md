# Isolated native verification

The ordinary `test` command verifies authoring structure. Native checks additionally require a local owned game, the pinned BaseLib package, .NET, a known Workshop content directory and Steam account-directory discovery. The toolkit distributes none of those game files.

`character.json` selects the branch. Preparation checks the owned `release_info.json` against [compatibility.json](compatibility.json): the imported baseline is regular 0.107.1/public-beta 0.111.0. Selecting regular while pointing at beta is refused. A new build requires an explicit reviewed compatibility-pin update and fresh evidence; a successful compile alone does not enable a native branch claim.

Run the project's pinned CLI, using your actual paths:

```powershell
python tools/character-builder/scripts/character-builder.py --project . prepare-lab --game-root "C:/your/Steam/steamapps/common/Slay the Spire 2" --baselib-root "C:/your/.nuget/packages/alchyr.sts2.baselib/3.4.7" --workshop-root "C:/your/Steam/steamapps/workshop/content/2868840" --steam-userdata "C:/your/Steam/userdata" --lab-id first-check
python tools/character-builder/scripts/character-builder.py --project . test-native --lab-id first-check --timeout 240
python tools/character-builder/scripts/character-builder.py --project . test
python tools/character-builder/scripts/character-builder.py --project . balance --comparator CHARACTER.IRONCLAD
```

Preparation compiles the ordinary release DLL, then a separate test DLL with `BUILDER_NATIVE_TESTS` enabled. It independently copies the owned game to `private/labs/<id>/game/`, excluding installed local mods and overrides. It copies only the chosen character and pinned BaseLib into that lab. Source links/junctions and overlapping/existing destinations are refused. Allow several GB of private disk space per lab.

The lab creates a **new** `Sts2CharacterBuilderLab-<random-token>` profile under Godot's application-data location (Windows AppData or Linux XDG data), with settings for discovered accounts. Workshop manifests are catalogued and disabled in that profile; only the local character and BaseLib are enabled. The original game installation and regular profiles are not edited. The lab and profile are preserved for inspection; there is no recursive cleanup command. The launcher currently recognizes Windows/Linux game executables; native behavior has been exercised locally only on Windows/v0.111.0.

Before launch, hashes of the copied game, mod/dependency bytes, request and initial profile settings must agree. A changed Workshop catalog, extra game file, linked path or changed project input invalidates preparation. The probe checks its exact Godot profile, marker, request token and loaded game/BaseLib/test-DLL hashes before replacing the save backend with an isolated `GodotFileIo`. It then waits for the menu and runs the native suite once. Tutorials are disabled only after the isolated profile is initialized. The test-only probe observes asynchronous authored-relic hooks and awaits them before changing rooms; entering Play phase alone does not imply those hooks have finished. Headless execution uses no interactive app window. Test DLLs embed debug symbols for private failure logs; normal release DLLs still exclude the probe. Event checkpoint controls start a fresh synthetic run per event, select a known event source, and force question-mark room rolls only in the test process; they exercise native pre-entry saves and real map-coordinate entry, not campaign generation/balance.

The native suite checks:

- Character/card registration and original icon loading; starter deck/relic identities and starter resource trigger.
- Every generated numeric card, base and upgraded, played through the native paid action path: targeting rejection, Energy, damage, Block, draw, resource gain, Exhaust/Power/discard disposal, completed action/table cleanup and card save round trips. Draw/Energy/Focus descriptions must match the active upgrade values. The recorded local fixture adds two test-only designs to exercise positive Energy gain and all-enemy damage combined with Block.
- Every generated card portrait in both upgrade states: decoded pixels/dimensions match the assigned SVG/PNG or shared fallback, cached textures are reused, and card save/load retains the selected texture. These checks require a fresh lab after a toolkit upgrade; old numeric-only evidence is incomplete. Human crop/style/legibility review remains separate.
- Authored item pools and native character/shared-pool exclusions; starter reward/shop exclusions; native relic reward or shop acquisition, exact effect deltas, repeated-turn policy, duplicate-trigger suppression, saved counters and combat reset. Potion purchase/reward, full-belt rejection, self-target rejection, duplicate queued-use suppression, consumption and save identities. Old evidence without current item coverage is incomplete.
- Authored event act/character/solo eligibility, visible native option buttons and localization, insufficient Gold and lethal-HP locks, stale affordability guards, exact unmodified costs/rewards, old/sibling duplicate selection, and Leave. Each event additionally tests initial checkpoint resume, interrupted rollback/replay and outcome persistence after leaving. Ordinary checkpoint semantics apply; arbitrary mid-callback saves are outside the contract.
- Authored Ancient first/repeat/late-repeat selection; other-character, omitted-visit/Ancient and anonymous-set fallback against the unpatched native selector. Each authored conversation checks visible text, speakers and next labels, native advancement/hotkey availability, reward-button access, and native map checkpoint reload/replay. Fixtures use synthetic solo runs and native visit statistics in the isolated backend; no production saved state is added. A native language switch and switch back verify English dialogue fallback and preservation of inline character/card/item localization. Human/translated layout review remains separate.
- Authored combat atlas bytes/pixels/cache, native-character exclusion, visual bounds and marker nodes; every state's frame rectangles, anchors, FPS, visible pixels, native triggers and repeated-action restarts. One-shot idle return, death final-frame hold/revive, native combat victory, new-combat reset and save/resume reconstruction. Fairy in a Bottle additionally runs through actual lethal damage and automatic potion activation: ordinary lethal-hit recovery, a held-death-pose control and a repeated lethal hit. These require exact HP/slot effects, the same visible authored sprite/atlas/anchors/scale and a working attack afterward. All three Fairy cases are required for current sprite evidence. These are runtime/geometry checks; human art/layout/device review and other room presentation remain separate.
- Every authored short PCM WAV cue: exact decoded PCM/rate/channel count, metadata-chunk handling, cache reuse, nonlooping playback, native character getters and attack/cast/death commands, both audio-manager overloads and gain. Master/SFX mute changes apply to active voices; foreign/native URI controls, the eight-voice limit and finished-node cleanup are checked, using a test-only two-second stream for duration-independent lifetime controls. Authored-atlas death checks cover the native non-Spine sound compatibility hook. Selection/transition use their native getter/manager routes without an interactive UI claim. Headless results do not prove audible quality or device behavior.
- Every configured rest/shop atlas: native attachment, exact frame crops/anchors/timing and visible pixels, shared texture cache, per-scene playback, native body exclusion, repeated-attachment guard, rest facing, foreign-character controls, successful native heal/purchase responses and rejected-action controls, repeated-action restarts, scene reentry/reset, cleanup and room reconstruction. Authored rest art additionally reconstructs idle after full native save/resume. Transactions and healing use native commands/synchronizers; this is integration evidence, not human room layout or co-op campaign evidence.
- Focus's native Block hook, actual turn transition, persistent combat counter and reset at the next combat.
- Native reward and merchant creation, including owner/pool membership.
- A permanent deck upgrade, full native run save/read/reconstruction/resume, and deck/relic/character identity plus potion-slot preservation.
- Actual native reward-card IDs, costs, dynamic values and rarity/type cells for each built-in character. These remain private evidence and can drive `balance --comparator`.

`test-native` emits progress and writes `evidence.json` under the lab. A success marker in `.builder/native-evidence.json` binds that file's hash. `test`, `balance --comparator` and package reports accept only complete current coverage with matching input/source/toolkit/release-DLL identity. Truncated, stale or failing evidence is not a native pass.

Each lab is one-shot. A timeout or interruption leaves its run marker; do not replay the mutation. Inspect `process.log`, `godot.log`, `progress.json`, `result.json` and `evidence.json`, fix the issue, then prepare a new lab ID. Preparation never reuses a dirty lab or resets existing profiles. The test-only probe is absent from a normal build and ZIP. A native pass establishes the numeric fixtures on the **reported** branch/build, not visual correctness, campaign balance, physical Deck/controller support, co-op, arbitrary extension effects or Workshop delivery. Keep those gaps visible. Existing character projects made with the earlier six-card prototype may need additional reward types before a normal merchant can populate; review/add cards through authoring data rather than renaming saved models.
