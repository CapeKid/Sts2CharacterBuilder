# Character builder implementation status

This implementation advances [issue #1](https://github.com/CapeKid/Sts2CharacterBuilder/issues/1); it does not close the full design's release gates. The original extraction plan remains at [character-builder-design.md](character-builder-design.md).

## Implemented

- Agent-neutral entry/resume workflow and 15 focused skills covering setup, mechanics, cards, art, items, events, dialogue, sprites, presentation, audio, correctness, balance, publishing and upgrades. Guided mode collects choices in short groups; expedited mode delegates creative defaults. Disabled custom content and delegated content have different outcomes.
- Python standard-library CLI: `init`, `doctor`, `validate`, `generate`, `resume`, `record`, `test`, `balance`, `build`, `stage`, `compare-delivery`, `prepare-lab` and `test-native`.
- A new local character repository with its own identity, original visible SVG placeholders, tracked lock/model IDs, explicit source ownership and an actual pinned Git submodule. No global skill installation. Existing destinations are refused.
- Strict authoring contracts and SHA-256 provenance; duplicate IDs/JSON properties, unsupported numeric effects, dangling deck references, unsafe paths, malformed assets and changed hashes fail checks. Generated-file conflicts are checked before mutation.
- A small conventional BaseLib 3.4.7/net9.0 character template with eight prototype cards, explicit upgrades, basic damage/Block/draw/Energy/Exhaust effects, a run-local Focus power and an optional starter relic. Optional per-card SVG/PNG portraits load declared assets without Godot imports or a PCK; unassigned cards retain the shared original fallback. The reward pool includes enough Attack/Skill/Power models for normal merchant population. Native deck/pool/relic/presentation fallbacks support skipped custom features. No cross-run progression is extracted.
- Optional design/items.json authoring for first-turn/each-turn starting, reward and shop relics plus combat-only self potions. Block/draw/Energy/Focus use native commands; item pools, generated descriptions, saved trigger counters and frozen model IDs are explicit. Missing/empty data preserves existing fallbacks. Native item icons remain runtime fallbacks.
- Optional design/events.json authoring for single-page solo encounters, act/character eligibility, bounded Gold/HP costs and Gold/healing rewards, generated English localization and an always-available Leave choice. Native checkpoint behavior and imagery are explicit; no custom save journal or co-op event protocol is introduced.
- Optional design/dialogue.json authoring for first/repeat conversations with eight ordinary Ancients. Character/Ancient/visit selection, original speaker/text lines, optional next labels and English localization fallback integrate with native advancement and reward buttons. Missing conversations preserve native results; no new saved state or reward behavior is added.
- Optional design/sprites.json combat atlases with exact declared SVG/PNG dimensions, per-frame crops/ground anchors, filter/scale, all six combat states, bounded one-shot timing and native bounds/markers. Native trigger/restart/death/revive/victory integration and reconstruction preserve other characters and add no saved state. Other room/screen presentation remains native fallback.
- Optional design/audio.json for short PCM16 WAV select/transition/attack/cast/death cues. Missing roles retain native routes; exact mod-specific URIs, live master/SFX controls, an eight-voice limit and finished-node cleanup isolate playback. RIFF chunks, sample format/duration and declared hashes are validated; no imported Godot resources or audio save state are required.
- Optional design/presentation.json for independent rest/shop SVG/PNG atlases, idle/action frames, ground anchors, position and scale. Only configured player scenes replace their native body; rest facing, accepted native rest choices, shop animation/purchase responses and scene reconstruction preserve native controls, transactions and saves. No combat sprite feature or new saved state is required.
- Optional selection portraits, locked portraits and background/fit in design/presentation.json, generated independently of room/combat sprites. Declared loose SVG/PNG art integrates with native selection, lock/unlock refresh and noninteractive background replacement, preserving native controls and other characters. Unassigned roles keep native imagery.
- Partial classes and explicit extension hooks allow project-owned cards, pools, starting kits and presentation without editing the submodule or generated files. Generated model IDs freeze after the first successful native build and remain tracked across clones.
- Hashed workflow evidence with conservative invalidation. Structural/compile/heuristic/delivery evidence is labeled separately. Builds record actual game metadata, references, inputs, source and DLL hashes.
- Closed, deterministic private-test ZIP staging from a current build receipt; only the project DLL/manifest, declared assets, license and package report ship. BaseLib is an external dependency. Exact downloaded-byte comparison rejects extra/missing files.
- Official-uploader publishing skill and preparation/delivery procedure, without using the reference mod's Workshop identity or live release.
- Disposable native labs with independent game copies, explicit account/mod discovery, unique profiles, byte/profile/catalog checks, a replaced save backend and one-shot test execution. The probe is conditionally compiled into a separate DLL and absent from normal builds/packages. Successful complete native evidence is invalidated when inputs/source/toolkit/release bytes change; the report can supply observed native pool cell targets to balance comparisons.

## Verified locally

On Windows, the behavioral suite exercises actual local submodule initialization, two distinct project identities/modes in paths containing spaces, a fresh recursive clone, pinned-toolkit checks, regeneration, extension preservation, saved-ID protection, invalid authoring data, stale evidence/builds, balance warnings and deterministic closed packages.

Generated custom-card/Focus and native-fallback/extension configurations compile against the locally owned **StS2 v0.111.0** assemblies with **BaseLib 3.4.7**. An independent Windows/headless game fixture additionally passed **99 native checks**: registration/icon load, starter deck/relic/resource, all eight bootstrap cards plus two fixture-only Energy/AoE cards in base/upgraded paid actions, upgraded draw/Energy/Focus text, Focus turn behavior, reward/shop membership, an upgraded deck saved/resumed through the game, relic identity preservation and resource reset in a new combat. It also verified decoded portrait pixels/dimensions and cache reuse in both upgrade states plus portrait preservation on card save/load, using an original SVG, a two-pixel PNG and shared fallbacks. Five authored relics and three potions additionally passed pool/shared/native exclusions, starter shop exclusion, native reward/shop acquisition, exact effects, repeated turns and combat reset, duplicate triggers/actions, full-belt/target rejection, consumption and saved identity checks. Full native save/resume preserves acquired potion slots as well as relics. Two authored solo events with four choices also passed act/foreign-character/co-op exclusion controls, visible native buttons/text, Gold/HP thresholds, locked/stale-choice rejection, exact outcomes, duplicate suppression, Leave, native pre-entry checkpoint resume/rollback/replay and persistence after leaving. These checkpoint controls use fresh synthetic runs and forced known room/event selection, not campaign evidence. Three authored Ancient conversations (Neow first/repeat and Darv first, including a one-line conversation) passed native visible text/speakers/advance labels, reward access and checkpoint replay. Selector controls preserved unconfigured/omitted and other-character results, including anonymous empty sets and late repeats. A native language switch and switch back verified English dialogue fallback and character/card/item inline text preservation; the template restores its own inline localization before native UI locale listeners run. It exported native pool counts and rarity/type cells from the installed build. The fixture exposed the earlier six-card prototype's insufficient merchant coverage; descriptions now also evaluate numeric Rules at render time so upgrade text follows the active values.

An original 12-frame SVG actor also passed all six combat sprite states: atlas pixels/cache, frame crops/anchors, visual bounds/markers, native triggers, repeated-action restarts, one-shot idle return, final-frame death hold/revive, actual native combat victory, new-combat reset and save/resume reconstruction. This is combat integration evidence; independent rest/shop integration is covered below, while transition/ending imagery and human 1280x800/style review remain separate. A two-pixel PNG atlas additionally passed portable dimension and shipped-byte checks.

Fairy in a Bottle also passed three native lethal-damage/automatic-potion regressions: ordinary recovery, a held-death-pose control and a repeated lethal hit. Each preserved the same visible authored sprite and atlas, idle anchors, scale and bounds, restored the expected HP, consumed only the Fairy and allowed an attack followed by idle. These use the real potion path rather than a direct revive-animation call. The existing runtime already handled it correctly; the new evidence gate requires all three cases.

Five authored sound cues also passed exact stereo PCM/rate/channel decoding with a padded metadata chunk, cache reuse and nonlooping playback. Native character selection/transition getters and the audio manager were exercised; actual attack/cast/death commands reached their configured cues. The fixture exposed the native death sound's Spine-only branch; a narrow character-owned compatibility hook now supplies the configured death cue for an atlas. Both manager overloads, live master/SFX mute and gain, foreign/native controls, eight-voice eviction and finished-node cleanup passed. A test-only two-second stream makes lifetime controls independent of authored clip duration. These are routing/mixing checks, not audible or human selection-screen review. The normal staged package contains the declared WAV and excludes the probe.

Independent rest/shop atlases additionally passed native attachment and body exclusion, frame crops/anchors/timing/visible pixels, repeated-attachment guards, rest facing, foreign-character controls, successful native healing and merchant purchases, rejected-action controls, repeated-action restart/idle return, scene reentry, cleanup and reconstruction. A native pre-entry rest map checkpoint and full run reload rebuilt the authored actor at idle; debug entry alone does not establish a saved room coordinate. The fixture retains ordinary transactions, controls and save semantics. A Windows progress-reader lock regression also passed: bounded replacement retries recover progress after reader release, while blocked final-evidence writes remain strict failures. The staged 15-file private package preserves declared room SVG bytes and excludes the probe. These are integration checks; human room layout/device/co-op review remains open.

Selection artwork additionally passed native screen initialization, decoded SVG/PNG pixels/cache, unlocked and locked portrait refresh, and the actual unlock animation including its glow texture. Focus-based native selection and button activation verified background fit/bounds, no input interception, foreign-character restoration, repeated replacement, cleanup and Back navigation. The fixture distinguishes visual animation locks from actual availability, restores its test-only availability control and verifies saved unlock IDs remain unchanged. These automated UI checks do not establish human layout quality or physical keyboard/controller/Deck behavior.

These results cover the generated numeric vocabulary on that build, not arbitrary custom effects or visual correctness. Dedicated lab profiles and a mocked save backend were used; no regular saves or Workshop items were modified. See [native testing](../builder/NATIVE-TESTING.md) and [the recorded fixture summary](native-character-fixture.json). All 15 skill files passed the skill-creator validator; the revised presentation skill was validated again. The local suite runs 44 tests (one host symlink capability skip), including four owned-game compile configurations and the probe branch without authored items/events/dialogue/sprites/audio/presentation. Room presentation, selection art and audio also compile with native cards, no Focus and combat sprites disabled; selection art additionally compiles without room presentation. The dialogue-authoring implementation and locale-reload fix passed all four Windows/Linux Python 3.11/3.12 CI jobs in PR #7.

## Remaining completion gates

| Design milestone | Remaining work |
| --- | --- |
| Portable foundation | Local behavioral evidence and a four-job Windows/Linux CI matrix exist; each change requires fresh results on its PR. |
| Native minimal character | Numeric lifecycle/resource/save-resume/reward/shop fixtures passed locally on v0.111.0. Visual selection/room/death/victory review and regular-branch build/native evidence remain missing. |
| Optional authoring | Skills and extension contracts exist; generic generators/native fixtures for branching/combat events, translated/ending dialogue, transition/ending presentation, hurt/victory/compressed/looped audio and bespoke item effects/art remain unimplemented. A flag records intent, not implemented behavior. Per-card SVG/PNG integration, bounded numeric relic/potion authoring, single-page solo events, ordinary Ancient first/repeat conversations, combat atlases, short PCM character cues and independent rest/shop atlases and selection art are implemented; human art/crop review and other presentation integration remain. |
| Verification/balance | Native comparator counts/cells and generated numeric base/upgrade fixtures now exist. Original full-pool completion, bespoke-effect fixtures, bounded archetype playtests, human balance observations and applicable controller/Deck/co-op evidence remain. The small bootstrap pool is not native-sized. |
| Publishing/clean-room delivery | Pinned official uploader integration, authorized private upload/new-item/update trials, authenticated visibility checks, downloaded hashes and an independently tested playable second character. The staging CLI alone does not satisfy this gate. |

Do not call an enabled optional feature complete merely because its skill exists. Reports keep unperformed native/device/distribution checks as gaps and never set `release_ready` true. The reference `sts2/`, `sheets/`, original content and publishing tools are untouched as runtime/package inputs.
